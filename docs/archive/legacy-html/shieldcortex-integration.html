ShieldCortex Integration

Why we'll integrate ShieldCortex into SmartAssist, and how it fills our security gaps

TL;DR

SmartAssist is great at learning from feedback (RLHF, Thompson Sampling, lesson lifecycle). ShieldCortex is great at protecting memory integrity (prompt injection firewall, credential scanning, contradiction detection). Together, they make a learning system that's also hardened against adversarial inputs. We'll integrate ShieldCortex's defence pipeline and contradiction detection while keeping our own RAG engine, lesson scoring, and feedback loop.

Why ShieldCortex?

Problem 1: Our Prompt Injection Defence is Basic

SmartAssist's prompt_inject.py uses simple regex pattern matching to detect injection attempts. This catches obvious attacks but misses:

  • Obfuscated injections — base64 encoded, Unicode tricks, homoglyph substitution
  • Semantic attacks — instructions that look like normal feedback but manipulate behavior
  • Indirect injection — malicious content hidden in files or URLs that get ingested into memory

ShieldCortex's 6-layer pipeline catches all of these with pattern detection, semantic analysis (embedding similarity to attack corpus), and behavioral scoring (entropy analysis).

Problem 2: No Credential Leak Protection

SmartAssist stores lessons, feedback, and context in plaintext JSON files. If an API key, token, or password accidentally ends up in a lesson or feedback entry, we have zero detection. It just gets stored and potentially injected into future sessions.

ShieldCortex scans for 25+ credential patterns across 11 providers (AWS, GitHub, Stripe, etc.) before anything touches storage.

Problem 3: No Contradiction Detection

SmartAssist can accumulate contradictory lessons over time. Example:

  • L042: "Always use snapshot tests for component rendering"
  • L089: "Never use snapshot tests — use toBeVisible() instead"

Currently these both live in the corpus and get injected, confusing Claude. We rely on manual merge_lessons to catch these. ShieldCortex detects contradictions automatically using semantic similarity.

What We Don't Need from ShieldCortex

ShieldCortex has its own memory engine (SQLite-backed, semantic search). We won't use this — our RAG system (LanceDB + bge-m3 embeddings + cross-encoder reranking + Thompson Sampling) is more sophisticated for our use case. We also don't need their Iron Dome action gates since we're not building autonomous agents that send emails or delete files.

What We'll Use vs Skip

ShieldCortex Feature Use? Reason
Defence Pipeline (6-layer scan) Yes Replaces our basic regex injection detection with production-grade scanning
Credential Scanning Yes Prevents API keys and tokens from leaking into lesson storage
Contradiction Detection Yes Auto-flags conflicting lessons for merge or retirement

Integration Points (Code Level)

1. Scan lessons before storage

In lesson_feedback.py — wrap _add_to_curated() with ShieldCortex scan:

from shieldcortex import scan

def _add_to_curated_safe(storage, lesson_text, category):
    """Add lesson to curated list after security scan."""
    result = scan(lesson_text)
    if not result.allowed:
        return None, f"Blocked by ShieldCortex: {result.reason}"
    return _add_to_curated(storage, lesson_text, category)

2. Scan feedback context in prompt_inject.py

Before processing user context from feedback signals, scan it:

from shieldcortex import scan

# In main(), before create_lesson_from_feedback():
if user_context:
    scan_result = scan(user_context)
    if not scan_result.allowed:
        # Log the blocked attempt, skip lesson creation
        log_blocked_injection(user_context, scan_result)
        user_context = None  # Don't create lesson from suspicious input

3. Scan MCP tool inputs

In mcp_server.py — scan lesson text in create_lesson() and compare_lesson():

# In create_lesson(), after quality gates:
result = scan(lesson)
if not result.allowed:
    return f"Blocked: {result.reason} (threat: {result.threat_level})"

4. Periodic contradiction scan

New CLI command smartassist scan-contradictions or as part of smartassist health:

# Load all curated lessons, check pairwise similarity
# Flag pairs with high similarity but opposing sentiment/action
# Suggest merge_lessons for contradicting pairs

Rollout Plan

1

Install & Validate Week 1

  • Install ShieldCortex Python SDK: pip install shieldcortex
  • Add to SmartAssist's pyproject.toml dependencies
  • Write integration tests: scan known injection patterns, verify clean lessons pass
  • Benchmark: measure latency overhead per scan (target: <50ms)
2

Defence Pipeline Integration Week 2

  • Wrap _add_to_curated() with scan gate
  • Add scan to create_lesson() and compare_lesson() MCP tools
  • Add scan to create_lesson_from_feedback() in hook
  • Add credential scanning to feedback context processing
  • Log all blocked attempts to security_events.jsonl for review
3

Contradiction Detection Week 3

  • Build pairwise lesson similarity scanner using ShieldCortex's semantic tools
  • Add smartassist scan-contradictions CLI command
  • Integrate into smartassist health output
  • Auto-suggest merge_lessons commands for flagged pairs
4

Dashboard & Monitoring Week 4

  • Evaluate ShieldCortex dashboard vs our current monitor terminal
  • If valuable: integrate security metrics into rag_dashboard MCP tool
  • Add blocked injection count, credential scan stats, contradiction count

Risks & Mitigations

Scan latency slows feedback loop Medium Benchmark first; async scan if >50ms; cache results for duplicate inputs
False positives block legitimate lessons Medium Log all blocks to security_events.jsonl; review weekly; add allowlist for common patterns
ShieldCortex dependency adds complexity Low Wrap all ShieldCortex calls in try/except — if it fails, fall through to current behavior
Python SDK vs npm (we're Python, they're primarily JS) Low Python SDK exists (pip install shieldcortex); if limited, use REST API mode

Prerequisites

Must fix first: MCP Server Connectivity

The SmartAssist MCP server doesn't currently connect in Claude Code (see Current Work doc). ShieldCortex integration depends on having a working MCP server since create_lesson() and compare_lesson() are MCP tools. Fix the MCP server connection issue before starting Phase 1.
