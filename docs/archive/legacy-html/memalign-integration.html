MemAlign Integration

How MemAlign's dual-memory system upgrades SmartAssist from pattern matching to cognitive alignment

TL;DR

SmartAssist already has the building blocks of MemAlign — lessons (semantic memory), feedback logs (episodic memory), and RAG injection (working memory). But our implementation is crude: keyword matching, static text, no principle extraction. MemAlign replaces this with cognitive-style memory that extracts actionable principles from natural language, stores edge-case examples, and constructs optimal context per query — all for $0.03 per alignment cycle. It's the brain upgrade our feedback loop needs.

What is MemAlign?

A Dual-Memory System for LLM Alignment

MemAlign (from Meta, integrated into MLflow/Databricks) aligns LLM behavior with human feedback using a dual-memory architecture inspired by human cognition. Instead of retraining the model, it builds a memory layer that captures expert preferences and uses them at inference time.

Key insight: a single natural-language explanation captures more signal than dozens of binary labels. When you say :) good use of theme colors instead of hardcoded values, that sentence contains intent, constraints, and guidance that a simple thumbs-up can't express.

The Three Memory Types

Semantic Memory Generalizable Principles

Stores distilled, reusable rules extracted from expert feedback. Not the raw feedback text — the actionable principle behind it.

Raw FeedbackExtracted Principle
:) good use of theme colors instead of hardcoded values"Always use semantic color tokens from the project's theme system. Hardcoded hex values create maintenance debt and break theme switching."
:( you should have run the tests before committing"Run yarn test --findRelatedTests on all changed files before every commit. Never commit untested code."
:) nice, you figured out which file to test"When writing tests, identify the correct test file by matching the source file's path pattern before creating new test files."

Notice how the extracted principles are richer and more actionable than our current hook-generated lessons, which are just regex-transformed versions of the raw text.

Episodic Memory Edge-Case Examples

Stores specific instances where the system failed or succeeded in unusual ways. These are concrete anchors for situations that resist generalization.

EpisodeWhy It's Stored
"Claude used ignoredTags instead of ignoredDomTags for react-native-render-html v6"API version mismatch — can't be captured as a general principle
"Claude deleted the hook instead of refactoring it when told to 'remove this hook'"Ambiguous instruction handling — edge case in interpretation
"Claude mocked internal code instead of mocking at the HTTP boundary"Testing anti-pattern — needs a concrete before/after example

We currently don't store episodic memory at all. Our feedback_log.jsonl has timestamps and signals but not the conversation context or the specific mistake.

Working Memory Dynamic Context Construction

At inference time, MemAlign constructs a task-specific context by combining:

  • All relevant semantic principles (filtered by topic similarity)
  • Most similar episodic examples (retrieved by embedding distance)

This is what our RAG injection does — but MemAlign does it with semantic similarity instead of keyword matching, and includes both principles AND concrete examples.

What Changes in Our Code

1. Lesson Creation: Regex → MemAlign Principle Extraction

Currently in prompt_inject.py, create_lesson_from_feedback() uses regex transforms (contractions, imperative form, quality gates). With MemAlign, this becomes an LLM call that extracts a principle:

# Before (current):
lesson = _context_to_lesson(user_context, sentiment)
# Returns: "Use theme colors instead of hardcoded values"

# After (MemAlign):
from memalign import SemanticMemory

semantic = SemanticMemory(storage_path)
principle = semantic.extract_principle(
    feedback=user_context,
    conversation_context=recent_messages,  # NEW: uses full context
    sentiment=sentiment,
)
# Returns: "Always use semantic color tokens from the project's theme
#           system (semanticColors.basic.text.primary) instead of
#           hardcoded hex values. This ensures theme switching works
#           and reduces maintenance when the design system updates."

The principle is richer, more specific, and includes the WHY — because MemAlign has access to the conversation context, not just the feedback string.

2. New: Episodic Memory Storage

When feedback relates to a specific edge case (not a generalizable rule), store the full episode:

# New file: episodes.jsonl
{
  "timestamp": "2026-03-05T16:00:00",
  "type": "failure",
  "context": "Claude used ignoredTags instead of ignoredDomTags",
  "resolution": "react-native-render-html v6 renamed the prop",
  "lesson": "Always check TypeScript definitions for the installed version",
  "category": "code_edit",
  "embedding": [0.023, -0.156, ...]  // for semantic retrieval
}

3. RAG Injection: Keywords → Semantic Working Memory

Currently prompt_inject.py extracts keywords and does vector search. With MemAlign:

# Before (current):
keywords = extract_keywords(user_message)
results = vector_search(keywords, top_k=5)
inject(results)

# After (MemAlign):
from memalign import WorkingMemory

wm = WorkingMemory(semantic_store, episodic_store)
context = wm.construct(
    query=user_message,
    task_type=detect_task_type(user_message),  # testing, git, code_edit...
)
# context contains:
#   - Top principles relevant to this task
#   - Most similar past episodes (successes and failures)
#   - Formatted for optimal LLM consumption
inject(context)

4. A/B Comparison → MemAlign Training Data

The lesson_comparison.jsonl file we just built becomes MemAlign's training input. Each pair (hook lesson vs Claude lesson) is a human-judgeable alignment example:

# Feed comparison pairs into MemAlign alignment stage
from memalign import align

align(
    examples=load_comparison_pairs(),  # from lesson_comparison.jsonl
    judge_feedback=human_preferences,  # which lesson was better?
    memory=semantic_store,
)
# MemAlign learns WHICH lesson style produces better principles
# and improves future extractions automatically

The A/B Comparison Connection

This is why the A/B comparison feature matters beyond just "which is better".

Right now we're building compare_lesson to log hook vs Claude lesson pairs. Once we have 20-50 pairs with human judgments ("this one is better because..."), those become MemAlign alignment examples. MemAlign uses those examples to learn our preferences and produce better principles going forward.

The pipeline becomes: A/B data → MemAlign alignment → better lessons → better A/B data → better alignment. A self-improving loop.
