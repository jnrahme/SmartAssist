SmartAssist + Pi Mono

How to use pi as a local coding worker to accelerate SmartAssist while keeping quality gates strict.

Local First Fast Iterations Deterministic Verification

1. Why Use Pi Mono Here

Pi is best for repetitive engineering work: scanning files, drafting focused patches, generating tests, and checking documentation drift. Keep architecture decisions and final acceptance human-driven.

  • You: architecture, behavior decisions, final merge/push.
  • Pi: scoped implementation, refactors, test scaffolding, audits.
  • Gate: compile + tests before push to main.

2. Setup

Install and Verify

npm install -g @mariozechner/pi-coding-agent
pi --version
pi --help

Provider Key (example: OpenAI)

export OPENAI_API_KEY="your_key"
pi --provider openai --model gpt-4o-mini "summarize this repository"

SmartAssist Local Push Gate

bash scripts/install-git-hooks.sh
bash scripts/pre-push-main.sh

This repo now has a pre-push hook that runs compile + test checks before any push.

3. Daily Workflow

Step A: Ask Pi for a Scoped Change

pi --provider openai --model gpt-4o \
"Refactor smartassist/hooks/vectorize_learnings.py for clarity only.
No behavior changes. Update tests if needed."

Step B: Verify Immediately

python3 -m compileall -q smartassist tests
uv run pytest -q

Step C: Repeat in Small Batches

Use small, testable diffs. Avoid large multi-file rewrites unless absolutely necessary.

4. Prompt Templates That Work Well

Audit Only (read-focused)

pi --tools read,grep,find,ls -p \
"Audit smartassist/mcp_server.py for regressions and dead code.
Return findings with file:line only."

Implement + Test

pi -p "Implement this bug fix in smartassist/tools/maintenance.py.
Add regression tests in tests/test_feedback_lesson.py."

Docs Drift Sync

pi -p "Compare docs/v2-system-design.html with current behavior in mcp_server.py.
Patch only incorrect statements."

5. Guardrails

  • Always require explicit file scope in prompts.
  • Do not trust output without running your gate.
  • Prefer small iterations over one large patch.
  • Use git push --dry-run origin HEAD:main to test flow safely.

Speed comes from tighter loops, not skipping verification.

6. Troubleshooting

Permission denied on push (403)

Fix GitHub credentials/token for the correct account before testing push behavior.

Hook not running

bash scripts/install-git-hooks.sh
cat .git/hooks/pre-push

Failing gate

Do not bypass with --no-verify while stabilizing SmartAssist.
